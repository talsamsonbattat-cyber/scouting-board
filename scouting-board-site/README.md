# The Scouting Board — live static site

FBS skill-position player-season database with NFL comparables. Static site on
GitHub Pages, data rebuilt weekly by GitHub Actions from the
CollegeFootballData.com (CFBD) API, live in-browser refresh through a tiny
Cloudflare Worker that holds your API key.

Personal, non-commercial use. All comparable stat lines are approximate —
verify on Sports-Reference CFB before relying on them.

## What's in the repo

    index.html                     the whole site (board + player pages)
    worker.js                      Cloudflare Worker proxy (holds CFBD key)
    cfbd_full_pipeline.py          data builder (run by Actions weekly)
    .github/workflows/refresh.yml  weekly scheduler + manual run button
    data/comp_library.json         ~100 NFL college-season reference lines
    data/manifest.json             ┐
    data/seasons_<conf>.json       ├ generated by the pipeline
    data/cfb_player_seasons.csv    ┘

## One-time setup (~20 minutes)

1. **CFBD key** — free at https://collegefootballdata.com/key

2. **Repo** — create a GitHub repo, push these files.
   Settings → Secrets and variables → Actions → new secret
   `CFBD_API_KEY` = your key.

3. **First data build** — Actions tab → *weekly-data-refresh* → Run workflow.
   It pulls current rosters, six seasons of stats, computes top-3 comps per
   row, and commits `data/`. (Or run locally: `pip install requests pandas`,
   `export CFBD_API_KEY=...`, `python cfbd_full_pipeline.py`.)

4. **GitHub Pages** — Settings → Pages → deploy from branch `main`, root.
   Your site is `https://<you>.github.io/<repo>/`.

5. **Worker (for the Refresh Now button)** — Cloudflare dash → Workers →
   create → paste `worker.js` → add secret `CFBD_API_KEY` → deploy.
   Edit `ALLOWED_ORIGIN` in worker.js to your Pages origin. Paste the worker
   URL into the site's Refresh Now dialog once; it's remembered.

## How updates work

| Layer | Refreshed by | Cadence | What it covers |
|---|---|---|---|
| Built data (`data/`) | GitHub Action | weekly Tue + manual button | full re-pull: rosters, all seasons, new players, comps |
| Live layer | Refresh Now in the site | whenever you click | current-season stat updates for already-known players, loaded conferences only |
| Your edits/comps | you, in the browser | instant | stored in localStorage, survive both refreshes above |

Stable key everywhere is `player_id` (CFBD athlete id) + `season_year`, so
nothing ever duplicates and your local choices stick to the right rows.

## Using the site

- Data loads **one conference at a time** (dropdown) to keep it calm; *Load
  All FBS* pulls everything. Tables paginate at 100 rows.
- Click a row → editor with stats, derived metrics, and the **top-3 comp
  candidates** — click a card to choose, or type a custom comp (custom wins).
- Player name → career page (`#/player/<id>`), one block per season.
- **Export CSV** → the 36-column spec schema, metadata header lines, sorted
  position → conference → school → name → season desc. Exports whatever
  conferences are loaded; the Action also commits a full-FBS CSV to
  `data/cfb_player_seasons.csv` every week.
- Edits are per-browser (localStorage). To carry them to another device,
  export CSV or copy the `sb_overlay_v1` localStorage value.

## Verify locally before going live (optional, no API key needed)

    pip install requests pandas
    python tests/mock_cfbd.py 8199 &                      # fake CFBD API
    CFBD_API_BASE=http://127.0.0.1:8199 CFBD_API_KEY=test \
      python cfbd_full_pipeline.py --season 2026 --earliest-year 2025 --with-games-current
    python -m http.server 8000                            # then open http://localhost:8000

You'll see the board running on fictional test data through the exact same
code path as production. `CFBD_API_BASE` also lets the pipeline run through
your Worker instead of hitting CFBD directly, if you ever want that.

## Caveats

- `games_played` comes from the box-score endpoint and only for the current
  season by default (`--with-games-current`); `games_started` isn't in CFBD —
  fill by hand where you care.
- ATH players are included and comped as WRs; edit the position on the row if
  a kid is really a RB/TE.
- Players with zero career stats are excluded by design.
- Free-tier CFBD: a weekly build is ~150 calls (+~135 with games). If runs
  start failing with 429s, drop the games flag or space runs out.
- Transfers: bio shows the current school; each season row shows the school
  where the stats actually happened.
- Comp library values are rounded approximations. Treat `data/comp_library.json`
  as yours — fixing a line or adding players immediately improves matches on
  the next build.
